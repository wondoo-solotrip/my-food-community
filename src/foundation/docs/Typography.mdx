# Typography

프리미티브 토큰(크기 · 두께 · 행간)을 조합한 **10종의 타입 스타일**이 실제 사용 단위입니다. 화면에서는 프리미티브를 직접 조합하지 말고 타입 스타일을 그대로 쓰세요 — 자간과 행간을 매번 다시 지정하는 실수를 막아줍니다.

## 서체

Pretendard Variable 단일 가변 폰트입니다. 파일 하나로 400–700 구간을 모두 커버하므로 두께별 추가 요청이 발생하지 않습니다.

<FontFamilyCard />

폰트는 `globals.css`의 `@font-face`로 로드하고 `/public/fonts`에서 서빙합니다. `next/font/local`을 쓰지 않은 이유는 `@storybook/nextjs-vite`에 `next/font` mock이 없어, `layout.tsx`에서 로드한 폰트가 스토리에는 적용되지 않기 때문입니다. 이 방식은 앱과 Storybook이 동일한 URL을 참조합니다.

---

## 타입 스케일

각 스타일은 `type-*` 유틸리티 클래스 하나로 적용됩니다. 아래 견본은 인라인 스타일이 아니라 **실제 유틸리티 클래스로 렌더**되므로, Tailwind 레이어가 깨지면 이 페이지에서 바로 드러납니다. 견본 문구는 `.pen` 컴포넌트에 있는 원문 그대로입니다.

<TypeScale />

```tsx
<h1 className="type-display-md">오늘의 맛을 발견하는 순간</h1>
<h2 className="type-heading-lg">함께 만드는 음식 이야기</h2>
<p  className="type-body-lg">좋아하는 음식을 기록하고 이웃과 경험을 나눠보세요.</p>
<span className="type-label-md">12분 전 업데이트</span>
```

`display`·`heading`은 행간 1.2(`tight`), `body`·`label`은 1.4(`normal`)입니다. 제목은 조밀하게, 본문은 읽기 편하게 두는 일반적인 원칙을 따릅니다.

## 토큰 이식 시 주의점

프리미티브 타이포그래피 토큰은 Tailwind `@theme`이 아니라 일반 CSS 변수로 선언했습니다. 디자인 파일의 이름(`font-size-300`, `font-line-height-tight`)이 Tailwind v4의 `--font-*` 네임스페이스와 충돌해, `@theme`에 넣으면 `.font-size-300 { font-family: 16px }` 같은 무의미한 유틸리티가 생성됩니다.

컬러는 사정이 다릅니다. 디자인 파일의 `color-*` 이름이 Tailwind의 `--color-*` 네임스페이스와 정확히 일치하므로, 이름을 유지한 채 `@theme`에 등록해 유틸리티까지 함께 얻었습니다.

      <C>spacing-*</C>,

      </span>,

### Storybook 문서 페이지에서의 캐스케이드

이 페이지의 견본 영역에는 `sb-unstyled` 클래스가 붙어 있습니다. Storybook 문서의 기본 타이포그래피 규칙은 **CSS 레이어 밖(unlayered)** 에 선언되어 있고, Tailwind 유틸리티는 `@layer utilities` 안에 있습니다. CSS 캐스케이드에서 **unlayered 선언이 layered 선언을 항상 이기므로**, 선택자를 아무리 구체적으로 써도 `type-*`의 `font-size`·`font-family`가 문서 스타일에 밀립니다.

`sb-unstyled`는 Storybook이 제공하는 공식 이스케이프 해치입니다(문서 규칙 선택자가 `:where(p:not(…, .sb-unstyled p))` 형태로 이 클래스를 제외합니다). **제품 코드에는 영향이 없습니다** — 경쟁하는 문서 스타일이 없으므로 `type-*`가 그대로 적용됩니다.
